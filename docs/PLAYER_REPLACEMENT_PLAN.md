# 播放器替换计划

## 背景

当前播放器基于 `AVPlayer` + 自定义 SwiftUI 控制层。用户希望点击画面时只在底部显示进度控制区，而不是在画面中央长期显示三个按钮；同时需要继续支持拖动进度、播放/暂停、快退快进、倍速、画中画、横屏、最小化播放条和同来源连播。

当前阶段不立即替换播放器。先解决并记录现有黑屏、YouTube 媒体时长异常和播放恢复问题，再进行播放器候选的隔离评估。

## 候选评估

| 候选 | 协议/风险 | 移植成本 | 初步结论 |
| --- | --- | --- | --- |
| SZAVPlayer | 需要以仓库当前 LICENSE 与依赖实际条款为准；在未完成许可证核验前不直接引入 | 中等，需适配现有 SwiftUI、PiP、横屏和本地 AVAsset | 可作为轻量控制层参考，不作为首选依赖 |
| VersaPlayer | 需要核验仓库 LICENSE、最近维护状态和依赖兼容性 | 中等到较高，需确认控制层是否能隐藏中央按钮并接入现有会话 | 作为第二候选，先做许可证和 iOS 17/Swift 5 构建验证 |
| Luna | 需要核验仓库 LICENSE、维护状态和资源/依赖体积 | 较高，需确认它是否适合本地分离音视频与当前 AVAsset 合成流程 | 暂不优先，除非控件交互明显更符合目标 |

## 推荐方向

优先考虑**不替换底层 AVPlayer，只替换控制层**：保留 `AVPlayer` / `AVPlayerItem` / `AVMutableComposition`，重做控制 UI 为“点击画面 → 底部进度条和控制区淡入；无操作后淡出”，中央不常驻三个按钮。这样能保留当前的本地文件、画中画、倍速、横屏和后台音频能力，移植风险最低。

如果现有黑屏或时间轴问题证明来自 AVFoundation 资源合成，而不是控制层，再评估开源播放器。正式引入前必须完成：

1. 阅读并记录仓库 LICENSE 和所有新增依赖许可证；
2. 确认 iOS 17、Swift 5 language mode、xtool/SwiftPM 构建兼容；
3. 用本地 `AVAsset` 和分离音视频样本验证时长、seek、结束事件；
4. 验证 PiP、横屏、倍速、后台音频和最小化会话；
5. 以独立分支或可回退提交接入，不直接覆盖当前播放器。

## 验收标准

- 点击画面只显示底部控制层，不遮挡画面中央；
- 拖动进度时不跳回、不乱序，时间显示与实际播放位置一致；
- YouTube 分离音视频和 Telegram 视频时长都准确；
- 播放结束后没有无画面尾部时间轴；
- 最小化、恢复、下一部、PiP、横屏和倍速不回归；
- 发生错误时能显示可读错误，而不是黑屏无反馈。
